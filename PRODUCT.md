# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

delegated: Next.js, React, TypeScript, Tailwind CSS, Shadcn/ui-style components, Lucide Icons, Framer Motion and Docker Compose deployment with an ASP.NET Core API.

## Users

Primary users are recruiters, technical interviewers, engineering managers and software teams evaluating Luara as a Back-End .NET developer.

## Product Purpose

The portfolio presents technical credibility, professional organization and a clear software-development profile centered on Back-End .NET, while also showing frontend familiarity.

## Positioning

The portfolio proves backend maturity through concrete architecture topics, API practices, relational database knowledge, delivery tooling and project structure, instead of relying only on a list of technologies.

## Operating Context

Visitors skim quickly on desktop and mobile, looking for role fit, stack, projects, education, certificates, contact paths and public code links.

## Capabilities and Constraints

The site must be responsive, production-buildable, deployable with Docker Compose, accessible by keyboard, readable in light and dark modes, and easy to personalize without changing the component architecture.

## Brand Commitments

Modern, professional, minimal, technically confident, with blue, white and dark gray as the main palette. Visual effects should be discreet and elegant.

## Evidence on Hand

The user supplied stack, content requirements, skill categories, architecture topics, desired tone and deployment intent. Real personal links, live project URLs, certificates and curriculum PDF are not supplied yet and must remain easy placeholders.

## Product Principles

1. Make the backend profile unmistakable in the first viewport.
2. Keep the interface clean enough for recruiters and technical enough for engineers.
3. Prefer clear proof sections over decorative excess.
4. Make every placeholder obvious and easy to replace.
5. Keep the site fast, responsive and deployable.

## Accessibility & Inclusion

Use semantic sections, keyboard-visible focus, readable contrast, responsive type, descriptive labels and motion that is subtle rather than essential.
